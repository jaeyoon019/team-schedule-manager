# team-schedule-manager — 팀플 일정 관리기

대학SW·AI입문 2차 팀과제 (팀 **콜론**). 작업별 소요 기간과 선행 작업을 입력하면, 한 작업이 밀렸을 때 뒤 작업이 며칠씩 밀리는지와 마감 안에 끝낼 수 있는지 알려 준다. 마감을 넘기면 조정안을 자동으로 제안하고, 사용자가 직접 넣은 일정도 평가한다.

## 주요 기능

1. 프로젝트 기간·마감일 입력
2. 작업별 소요 기간·최소 기간·선행 작업·예정 시작일 입력
3. 선행 관계 검사(A→B→A 같은 순환이면 오류) → 기본 일정 계산
4. 지연 입력 → 후속 일정 재계산
5. 마감 안에 끝나는지 판정
   - 끝나면 → 최종 일정 출력
   - 넘기면 → 조정 가능한 작업을 모두 최소 기간으로 놓고 다시 계산
     - 그래도 넘기면 → 조정 불가, 최소 초과 일수 표시
     - 맞으면 → 자동 조정안을 만들어 기존 일정과 비교 → **적용 / 직접 입력 / 종료**
6. 직접 입력 → 평가 → 문제점·완료일·여유 또는 초과 일수 출력 → **다시 입력 / 제안 적용 / 종료** 반복
   - 사용자 입력은 몰래 고치지 않는다. 규칙을 어기면 적용하지 않고 문제가 있는 작업만 알려 준다

**가정**: 일 단위로 계산하고, 서로 관계없는 작업은 동시에 진행할 수 있다고 본다. 담당자별 일정 충돌 검사는 추가 기능으로 미룬다.

## 공통 약속(확정)

- **날짜는 `datetime.date`로 통일**하고, 기간은 `int`(일)로 쓴다. `st.date_input`이 `date`를 돌려주고 Plotly 간트도 그대로 받는다
- **완료일 = 시작일 + 기간**. 완료일은 "다음 작업이 시작할 수 있는 날"이다. 예: 11/2 시작, 4일 → 완료일 11/6
- **작업 묶음은 `dict[str, Task]`** (ID → Task)

- 평가 4가지: 최소 기간(입력한 기간 ≥ `min_duration`), 선행 관계(선행 작업이 끝난 뒤에 시작), 완료 작업 변경(`status`가 `"완료"`인 작업은 시작일·기간이 원래와 같아야 함), 마감 준수(`days_over`가 0 이하)

- 마감 준수 문제는 작업이 아니라 전체 일정의 문제라서 `problems`에서 작업이 `"전체"`로 표시된다
- **`app.py` 호출 순서**: `evaluate_plan` → `summary_text` → `make_problem_table` → (`schedule`이 `None`이 아니면) `make_result_table`, `make_gantt`

## 정한 기준 (2026-10-27)

1. **지연 = 그 작업이 원래보다 며칠 더 걸리는지** (`delay`). 실제 기간 = `duration + delay`
   - 시작이 늦어진 건 `planned_start`를 고쳐서 표현한다
   - 자동 조정안의 "이미 생긴 지연은 고정"은 `delay`를 건드리지 않는 것으로 처리한다
2. **마감 판정 = `완료일 <= 마감일 + 1일`**. 완료일은 "다음 작업이 시작할 수 있는 날"이라, 이렇게 해야 마감일 당일까지 작업할 수 있다
   - 예: 마감 11/20이면 완료일 11/21까지 통과, 11/22부터 초과(1일)
   - `adjust.py`와 `evaluate.py`는 이 식을 직접 쓰지 않고 **`days_over`를 불러** 쓴다 (통과 = `days_over(...) <= 0`)

## 예시 데이터 (테스트 공용)

| ID | 기간 | 최소 | 선행 | 예정 시작 |
|---|---|---|---|---|
| A | 4 | 3 | — | 11/2 |
| B | 5 | 3 | A | 11/6 |
| C | 3 | 2 | B | 11/11 |
| D | 7 | 5 | — | 11/2 |
| E | 2 | 1 | D | 11/11 |

기대 결과 (시작 → 완료):

| 경우 | A | B | C | D | E | 전체 완료 |
|---|---|---|---|---|---|---|
| 기본 | 11/2→11/6 | 11/6→11/11 | 11/11→11/14 | 11/2→11/9 | 11/11→11/13 | **11/14** |
| A 지연 1일 | 11/2→11/7 | 11/7→11/12 | 11/12→11/15 | 그대로 | 그대로 | **11/15** (A·B·C 각 +1) |
| D 지연 1일 | 그대로 | 그대로 | 그대로 | 11/2→11/10 | 11/11→11/13 | **11/14** (E는 예정 시작이 11/11이라 안 밀림) |

- 순환 예시: A의 선행에 C를 넣으면 A→B→C→A → `CycleError`
- `topo_sort` 결과 순서는 하나로 정해지지 않는다(예: `A, D, B, E, C`). 테스트는 "선행 작업이 앞에 오는가"만 확인한다
